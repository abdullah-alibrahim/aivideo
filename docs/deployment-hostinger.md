# Deploying AI Reels Studio to Hostinger Shared Hosting

This guide deploys the Laravel web studio to an existing Hostinger shared-hosting
account (`u817201413`, app `ai-yellowspace`). The app renders with the local
PHP/FFmpeg driver; the Python renderer stays for desktop use only.

## 1. Account prerequisites

Verify these on the Hostinger account before deploying:

| Requirement | Detail |
|---|---|
| SSH access | Enabled in hPanel (Advanced → SSH Access) |
| PHP CLI | `/opt/alt/php84/usr/bin/php` (or whichever Alt-PHP is installed) |
| MySQL | Database + user created in hPanel (MySQL Databases) |
| FFmpeg / FFprobe | Installed under the account, e.g. `$HOME/bin/ffmpeg`, `$HOME/bin/ffprobe` |
| Composer | Available as `composer` or `composer.phar` |
| Node/npm | Needed only if you build frontend assets on the server |
| `proc_open` | Must not be disabled for the CLI PHP pool (web pool may disable it) |
| Outbound HTTPS | Needed for Gemini / ElevenLabs provider calls and mail |

If `proc_open` is disabled for the web PHP pool, `/cron-run/{token}` reports
`needs_cli_worker` and jobs stay queued for the CLI worker instead.

## 2. Document root

Point the domain (or subdomain) document root to:

```
/home/u817201413/apps/ai-yellowspace/laravel-app/public
```

Do **not** expose `laravel-app/` source, `vendor/`, `.env`, or storage outside
`public/`. `.env`, `vendor`, and `storage` are not web-accessible by default
when the document root is `public`.

## 3. Upload the application

Upload the repository contents (or use git on the server). Notable exclusions:

- `public/build` is gitignored — build it locally and upload, or run
  `npm ci && npm run build` on the server (step 5).
- `vendor/` is not uploaded — run `composer install --no-dev` on the server.
- `.env` is not uploaded — create it from `.env.hostinger.example` (step 4).
- `storage/` directories that hold user data (database, videos, keys, logs)
  should be persistent; do not overwrite them on redeploy.

## 5. Install and build

```bash
# PHP dependencies (production)
composer install --no-dev --optimize-autoloader --no-interaction --prefer-dist

# Frontend assets (either build here or upload public/build from local)
npm ci --no-audit --no-fund
npm run build
```

If the server lacks Node, build `public/build` locally (`npm run build`) and
upload the entire `public/build/` directory. Remember `public/build` is
gitignored, so it must be transferred separately on every frontend change.

## 6. Database and storage

```bash
php artisan migrate --force --no-interaction
php artisan db:seed --class=FreePlanSeeder --force --no-interaction
php artisan storage:link --relative --no-interaction
```

`storage:link` creates `public/storage` → `storage/app/videos` so rendered
media, thumbnails, subtitles, and previews are served through
`/storage/…`. Re-run it if the link is removed during a redeploy.

## 7. Bootstrap the first administrator

There is no public registration. Create the initial Studio administrator from
the CLI:

```bash
php artisan studio:make-admin --if-missing
```

It will prompt for name, email, and password (min 12 chars). On shared hosting
run this once interactively over SSH. Subsequent deploys must not re-run it
unless you intend to promote another account (`--if-missing` is idempotent).

## 8. Cache configuration

```bash
php artisan config:cache --no-interaction
php artisan view:cache --no-interaction
php artisan route:cache --no-interaction
```

`route:cache` works because all routes are controller-based (no closures).
Clear caches before a redeploy with `config:clear`, `view:clear`, `route:clear`,
then re-cache.

## 9. Schedule and queue worker

Shared hosting has no systemd/supervisor. Use cron:

### Schedule (runs `schedule:run` every minute — drains the bounded queue)

Add via hPanel → Cron Jobs or `crontab -e`:

```cron
* * * * * /opt/alt/php84/usr/bin/php /home/u817201413/apps/ai-yellowspace/laravel-app/artisan schedule:run >> /dev/null 2>&1
```

The schedule runs one queue job per invocation (`queue:work --stop-when-empty --max-jobs=1`) plus stale-render recovery and daily pruning.

### Persistent worker loop (optional, faster job pickup)

```bash
nohup bash scripts/queue-worker-loop.sh >> storage/logs/queue-worker.log 2>&1 &
```

Stop with `pkill -f queue-worker-loop.sh`. The loop and cron are safe to run
together because the database queue uses row locking.

### Web trigger fallback (`/cron-run/{token}`)

If neither cron nor the worker loop is available, a signed web request can
drain pending jobs:

```cron
* * * * * curl -fsS "https://your-domain.example/cron-run/{CRON_SECRET}" >/dev/null 2>&1
```

Keep `CRON_SECRET` strong and secret. When empty, `/cron-run` is disabled
(404).

## 10. PHP limits (hosting)

Ask Hostinger support or check MultiPHP INI for these, and raise them if
renders time out:

- `max_execution_time` (CLI): at least 1200 s
- `memory_limit`: at least 256 M
- `upload_max_filesize` / `post_max_size`: match `STUDIO_MAX_VIDEO_MB` (100 M)

The Laravel render lock defaults to 900 s (`STUDIO_RENDER_LOCK_SECONDS`); keep
the CLI timeout above the longest expected render.

## 11. Verify

```bash
php artisan studio:doctor
```

Expected production result: all critical checks pass. Remaining warnings are
environment-specific and acceptable on this machine:

- **FFmpeg executable / FFprobe executable**: report the configured
  `/home/u817201413/bin/…` path; fail only if the binary is missing or not
  executable on the Hostinger account.
- **Arabic font**: report the `AIVIDEO_FONTS_DIR/NotoKufiArabic.ttf` path;
  upload `Amiri-Regular.ttf` and `Tajawal-Regular.ttf` to the same directory
  so the Amiri/Tajawal font options resolve.
- **Cron secret**: warning if `CRON_SECRET` is empty; set it to enable
  `/cron-run`.
- **Built assets**: requires `public/build/manifest.json` (upload or build).
- **Storage link**: requires `public/storage` → `storage/app/videos`.

Also confirm:

- `https://your-domain.example/` shows the landing page
- `https://your-domain.example/login` shows the login form
- An administrator can log in, access `/admin/invitations`, and create invites
- A member invited via email can accept, set a password, and render a reel

## 12. Asset strategy (fonts + builds)

- `public/build` is gitignored and generated by Vite. Build locally or on the
  server and upload `public/build/` with each frontend change.
- `python_engine/fonts/NotoKufiArabic.ttf` is tracked. `Amiri-Regular.ttf`
  and `Tajawal-Regular.ttf` are **untracked** (locally present, not committed).
  Upload those two `.ttf` files to `AIVIDEO_FONTS_DIR` on Hostinger so the
  corresponding subtitle/font options work. Do not commit them unless you want
  them tracked.

## 13. Remaining manual Hostinger steps (no code change)

1. Create the MySQL database and user in hPanel; note credentials for `.env`.
2. Create/verify the SMTP mailbox (`MAIL_USERNAME`) at `smtp.hostinger.com:465`.
3. Install FFmpeg + FFprobe with H.264/AAC/libass support under `$HOME/bin` or
   adjust `AIVIDEO_FFMPEG_BIN`/`AIVIDEO_FFPROBE_BIN`.
4. Confirm `proc_open` is enabled for the CLI PHP pool (web pool may disable it).
5. Point the domain document root to `laravel-app/public`.
6. Add the `schedule:run` cron job (every minute).
7. Start the queue worker loop (recommended) or configure `/cron-run` curl.
8. Run `php artisan studio:make-admin` once interactively over SSH.
9. Add `https://your-domain.example/auth/google/callback` to Google Cloud
   Console if using Google OAuth.
10. Set strong `CRON_SECRET`, `APP_KEY`, `STUDIO_ADMIN_EMAIL`, and MySQL/SMTP
    passwords in `.env`; never commit `.env`.
